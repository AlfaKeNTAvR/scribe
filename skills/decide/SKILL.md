# Record a decision

Use this before the first edit that implements a choice, not after. A record
written after the code is a summary; a record written before it is the decision.

## 1. Fill the spec

Write a JSON object with the keys below to a temp file (for example
`/tmp/scribe-spec.json`). Everything with an identity or a lifecycle meaning
(`id`, `alias`, `date`, `review_state`, `effective_state`, the ratification
fields, `implementation_links`, `history`) is generated by scribe: do not put it
in the spec.

Front matter keys: `title`, `task_refs`, `decided_by`, `recommended_by`,
`provenance`, `affects`, `tags`, `reversibility`, `blast_radius`, `regret_when`,
`review`, `verify`, `supersedes`, `relates_to`.

Body keys: `y_statement`, `question`, `criteria`, `constraints`, `options`,
`decision`, `consequences`, `attempted_and_failed` (optional),
`evidence_quote`, `evidence_pointers`.

```json
{
  "title": "One sentence naming the choice and its mechanism",
  "decided_by": "agent-recommended",
  "recommended_by": "claude-code",
  "provenance": {"authored_by": "agent-drafted", "agent": "claude-code", "trigger": "user-prompt"},
  "affects": [{"type": "path", "pattern": "src/**/*.py"}],
  "tags": ["schema"],
  "reversibility": "two-way-door",
  "blast_radius": "component",
  "regret_when": "The condition under which this turns out to be wrong",
  "review": "2026-12-08",
  "y_statement": "In the context of ..., facing ..., I decided ... to achieve ..., accepting ...",
  "question": "What is being decided and why now",
  "criteria": "- What a good answer has to satisfy",
  "constraints": "- What is fixed, and every assumption filled in by the agent",
  "options": [
    {"option": "The chosen option", "for": "...", "against": "...", "evidence": "...", "chosen": true},
    {"option": "A rejected option", "for": "...", "against": "...", "evidence": "...", "why_rejected": "..."}
  ],
  "decision": "What will be done, concretely",
  "consequences": "- Positive, negative, requires, measure",
  "evidence_quote": "the decisive user turn, verbatim",
  "evidence_pointers": ["session id, date, file and line of the source"]
}
```

Rules for the spec:

- `evidence_quote` is the decisive user turn copied verbatim, never a paraphrase
  and never your own summary. Transcript pointers go in `evidence_pointers`; they
  are context, not proof.
- For a decision nobody asked for, write `(no user turn; self-initiated)` as the
  `evidence_quote` and set `provenance.trigger` to `self-initiated`.
- `options` needs at least two entries and exactly one with `"chosen": true`.
- Leave `task_refs` out unless you know the tracker id: scribe fills it from the
  session state.

## 2. Write the record

```
uv run --frozen --project ${CLAUDE_PLUGIN_ROOT} scribe new --spec /tmp/scribe-spec.json --register --session "${CLAUDE_SESSION_ID}"
```

A validator error means nothing was written: fix the spec and run it again.

## 3. Confirm

Read the path scribe printed and confirm the record to the user in one line:
the alias, the title, and that it is unreviewed.

## One-way-door decisions

With `reversibility: one-way-door`, do not stop and do not perform the action.
Leave the record `unreviewed`, continue with every task that does not depend on
it, and list all pending one-way-door aliases in a single `**Next:**` block at
the end of the run. Block early only when the remaining work cannot proceed
without the answer.

## Replacing an existing decision

When this decision replaces an earlier one, set `supersedes` to the earlier
record's alias, even when that record is already ratified. The index puts the
new record at the top of the review queue and the CI check blocks the merge
until a human reviews it. Never edit or delete the earlier record.
