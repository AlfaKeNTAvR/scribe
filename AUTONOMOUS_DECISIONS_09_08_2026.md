# Autonomous decisions, 2026-09-08, scribe build pipeline

Mode: autonomous, owner-approved five-step pipeline (`research/decision-scribing/build-brief.md` in the `~/.claude` repo). Each step appends its own numbered items below. Plan items are `P`, review items should be `R`, revision items `V`, implementation items `I`.

## Step 1, planner (Fable 5.1), plan written to `docs/build/01-plan.md`

- P1. Python package `src/scribe/` with console script `scribe` (`uv run scribe ...`), project name `scribe`. Reason: `python -m scribe` and `scribe` read the same in hooks, skills and docs; the `src` layout keeps tests from importing the working copy by accident. Rejected `scribe_core/`: the extra word buys nothing since the package is never published.
- P2. Runtime dependency: PyYAML only. Reason: front matter has nested lists of flow mappings (`history`, `affects`, `verify`); a hand-written subset parser would be the riskiest module in the repo. ULID is implemented in the standard library (48-bit ms timestamp plus 80 random bits, Crockford base32), no `python-ulid` dependency. Dev dependency: pytest.
- P3. `requires-python = ">=3.11"`, `.python-version` pinned to `3.12`. Reason: the workstation has system Python 3.10 and a uv-managed CPython 3.12.14; no 3.11 is installed, so a 3.11 pin would force a download. The git hook shims run under system `python3` (3.10 is enough for an `os.execvp` call).
- P4. Record filename is the alias (`docs/decisions/D-YYMMDD-slug.md`), ULID inside. Reason: humans read filenames and `git log --stat`; a same-alias collision between branches shows up as an add/add merge conflict, which is the visible failure; lint flags `duplicate_alias` if both survive.
- P5. `decided_by` enum simplified to `human | agent-recommended | agent` from README 10.2's `user-ratified | model-recommended, user-accepted | model-default, unreviewed`. Reason: the README values contain commas and spaces, which need quoting in YAML and break `grep`-style indexing; the meaning is unchanged and documented in plan section 3.2. The three hand-written records use `human` as instructed by step 0.
- P6. Commit trailer format `Decision: <alias> <ulid>`, both tokens, space separated. Reason: the alias makes `git log` readable, the ULID is the identity that survives alias collisions; the lookup accepts either token alone for hand-written trailers.
- P7. Scratch state lives at `<worktree>/.claude/scribe/state.json` (README 10.4), not at `docs/decisions/.scratch/` which the bootstrap `.gitignore` anticipates. Reason: README is the design source of truth; `docs/decisions/` should contain only records, the index and the attestation file. `scribe init` appends `.claude/scribe/` to `.gitignore`; the existing `docs/decisions/.scratch/` line is harmless and can be removed by the implementer.
- P8. Ratification attestation: `docs/decisions/RATIFICATIONS.jsonl`, append-only, one line per verdict with the record's body SHA-256, is the "path the agent's deny rules block". A record with `review_state: ratified` and no matching attestation is invalid. Reason: the record file itself must stay agent-writable (the agent writes and updates records), so the human-only path has to be a separate file. Limits: the agent can still run `scribe ratify` via Bash; the CLI tags such entries `via: claude-code` when the `CLAUDECODE` env var is present (UNVERIFIED). Raised as R3 in the plan.
- P9. Phase 3 gates run in shadow mode: they compute the verdict, append it to `.claude/scribe/gate-log.jsonl`, and exit 0. `SCRIBE_GATES=enforce` flips them to exit 2 and only tests set it. Reason: the brief wants them scaffolded fail-open, and the owner wants one-way-door frequency measured before anything heavier (A13); a log gives that number for free.
- P10. `scribe check` (CI) scopes the supersede rule to records added or modified between the base ref and HEAD, not to every record in the tree. Reason: a pre-existing case that reached `main` before branch protection would otherwise fail every PR forever.
- P11. The dropped CI workflow installs scribe with `uvx --from "$SCRIBE_SOURCE"` where `SCRIBE_SOURCE` is a placeholder git URL, because the scribe GitHub repository does not exist and must not be created without asking. Rejected: vendoring a standalone checker script into each target repo (drifts from the package). Open question for the owner: create the repo and tag `v0.1.0`, or prefer vendoring.
- P12. Git hooks are installed as Python shim files (`#!/usr/bin/env python3`, `os.execvp` into `uv run --frozen --project <PLUGIN_ROOT> scribe git-hook <name>`), with the plugin root baked in at `scribe init` time. Reason: brief forbids bash hooks; a shim keeps the hook file tiny and fail-open (missing `uv` prints one line and exits 0). Cost: if the plugin moves, `scribe init --force` must be re-run; the shim carries a `# scribe-managed v1` marker so init can tell its own hooks from foreign ones.
- P13. DEMM grades live in `docs/build/01-records-grading.md`, not in the record bodies. Reason: the body section list is fixed and validated; a grade is review output, not part of the decision.
- P14. `scribe index` is read-only over records (writes only `INDEX.md`); rebuilding `implementation_links` from git trailers is a separate `scribe relink` command. Reason: README 10.4 says "the indexer rebuilds links", but a generator that silently mutates records makes `index --check` in CI a side-effecting step; splitting keeps CI pure.
- P15. `post-commit` marks a record `implemented` and adds a link only when the commit changed paths outside `docs/decisions/`. Reason: the commit that adds the record itself is not its implementation.
- P16. A `SessionStart` hook is added although the brief's phase 2 list does not name it. Reason: `prepare-commit-msg` needs a session id in scratch state before the first prompt-triggered write, and the first `uv run` after install is slow; SessionStart pays that cost with a 120 s timeout so edit-path hooks stay under 1 s. It also prints the review-queue count as context when non-zero.
- P17. `verify` entries (grep engine) are executed by `scribe lint` only, not by `commit-msg` or `scribe check` in this run. Reason: `commit-msg` is warn-only and time-sensitive; running greps over globs there adds latency for a warning nobody acts on yet. README 10.4 schedules them in commit-msg and CI; deferred, logged.
- P18. The validator requires at least one blockquote line in `## Evidence` (the verbatim decisive turn, A12) and an `## Options considered` table with exactly one `chosen` row. Reason: these are the two properties DEMM grades as "who decided" and "what was rejected"; making them structural keeps agent-written records from omitting them.
- P19. PreToolUse injection is emitted as `{"hookSpecificOutput": {"hookEventName": "PreToolUse", "additionalContext": ...}}`. UNVERIFIED against the brief's plugin facts; fallback is plain stdout. Isolated in one module so a fix is one edit.
- P20. The three hand-written records are `review_state: ratified`, `ratified_by: "@nikita"`, with attestation lines `via: hand-written` in `RATIFICATIONS.jsonl`, body hashes computed by the planner. Reason: the owner made these decisions in the interview; writing them as unreviewed would misstate who decided. Timestamps `2026-09-08T20:37:41Z` to `:43Z` match the ULID timestamp prefixes (system clock at generation).
- P21. `affects` entries of `type: package` are accepted by the validator but ignored by the edit-time matcher in this run; a third type `action` is reserved for the Bash denylist (plan 4.7). Reason: only path matching has a consumer today.
- P22. Hook stdin field names (`session_id`, `cwd`, `tool_input.file_path`, `tool_input.command`, `stop_hook_active`, `last_assistant_message`, `prompt_id`) are used as commonly documented but marked UNVERIFIED in the plan because the brief's verified facts do not list them. Every read is tolerant of absence.
- P23. Injection budget: at most 5 records, 220 characters per line, 1600 characters per block; internal deadline 700 ms; hooks.json timeout 3 s for edit-path hooks. Reason: README asks for "budget bounded, under 1 second"; the numbers are starting points for step 5 to measure.
- P24. The plan has 16 tasks (T1 to T16), ordered so `uv run pytest` is green after each; T10 (git hooks) is the only L-sized task. Reason: git hooks touch three entrypoints and real git in tests; splitting them would leave the repo in a state where trailers are added but never consumed.
- P25. `commit-msg` honours `SCRIBE_COMMIT_MSG=enforce` already (exit 1 on unknown or invalid decision references) although this run ships it warn-only. Reason: the flip to enforce should be a config change later, not new code.

## Main session decisions (Fable 5.1, step 0)

- M1. The step 4 Codex orchestrator commits after each finished task with plain `git commit` in the commit skill's format (type: Title, one-sentence body, `Decision:` trailer where a task implements a record). The owner's rule "always use /commit" binds Claude sessions; Codex is a different tool and has no access to the skill. Per-task commits were chosen over one big commit at the end because Codex runs in 9-minute slices and a slice can die mid-write; a commit boundary per task is what makes "re-run the task, never patch by hand" safe. Nothing is pushed. The main session's own commits (pipeline files, review) go through /commit.
- M2. Pipeline scripts and prompts live in `docs/build/pipeline/` inside the scribe repo rather than the job tmp dir, so the handoff chain is auditable from git alone and the worktree hook (which rejects complex inline commands) is satisfied by `bash <script>`.

## Step 3 reviser decisions (Fable 5.1), plan v2 written to `docs/build/03-plan-v2.md`

- R1. Supersession edge is effective only while the successor is not rejected and its `effective_state` is `proposed`, `implemented` or `superseded`; a shared `reconcile_supersession` marks and restores predecessors (new history event `restored`) from `scribe new`, `ratify`, `reject` and `lint --expire`, while `scribe index` stays read-only. Reason: F1 needed one rule that both the indexer and the injection hook apply, and P14's pure indexer was worth keeping.
- R2. Repeated `ratify` or `reject` with the same verdict is an idempotent exit 0 (v1 said exit 1), and reversals in both directions are allowed. Reason: the F8 recovery path (attestation written, record write crashed) is healed by re-running the same command, which only works if repeats are not errors.
- R3. Attestation line is written before the record change and is the authority; a record left `unreviewed` behind an attestation validates as `state_behind_attestation`. Reason: the file the deny rule protects should never lag the record, and a retry heals the other direction for free.
- R4. Ratification authority in this release is by construction (`disable-model-invocation: true`, the skill's inline `!` command, an anchored `Edit` deny rule, an explicit `--via`), not by proof; `CLAUDECODE` detection dropped; no `Bash(*scribe ratify*)` deny rule. Reason: the skills doc says a matching deny rule aborts skill-injected commands too, so that rule would break the human path, and no documented signal identifies a Claude Code subprocess. Q5 added.
- R5. `SCRIBE_GATES` and `SCRIBE_COMMIT_MSG` move from environment variables to `.claude/scribe/config.json` (git-ignored, `version: 1`), keeping their names. Reason: F21's inherited-environment risk, and keeping the name keeps record A13's `verify` entry (`SCRIBE_GATES` in `pre_tool_use_gate.py`) truthful without touching the record.
- R6. `body_sha256` pinned to `rstrip()` of the text after the closing `---` line (CRLF normalized); front-matter YAML comments are not preserved on save. Reason: only the `rstrip` definition reproduces the three committed attestation hashes (checked with a script); PyYAML cannot round-trip comments and the comments are not keys.
- R7. Edit-path hook `timeout` set to 1 second in `hooks.json`, internal deadline 700 ms kept, timing test measures the whole `uv run` subprocess (warm median under 1.0 s, bytecode-cold printed and bounded at 2.0 s) and fails rather than skips without `uv`. Reason: the docs state a timed-out PreToolUse hook is cancelled and the call proceeds, so the timeout is the mechanical fail-open ceiling the brief asks for; a fresh-venv cold start is not measured because it needs network.
- R8. Implementation links are recorded only for changed paths matching the record's `affects` (all non-`docs/decisions/` paths when `affects` has no path entries), one function `links.implementation_paths` shared by `post-commit`, `relink` and `scribe check`. Reason: F3 and F11 both needed a definition of "this commit implements this record", and without it the T1 bootstrap commit (which touches `docs/build/`) would have counted as implementing all three records.
- R9. `scribe init` writes the CI workflow only with `--ci-source <path or URL>`; `.` means the repository is the scribe checkout (dogfood). Reason: F6; vendoring a checker rejected as in P11; withholding keeps every PR from failing on a placeholder.
- R10. `UserPromptSubmit` extracts tracker ids from the prompt text into `task_refs` and `scribe new` consumes them; Claude Code task identity (`TaskCreated`) is deferred as a non-goal. Reason: F10 asked for task correlation or an explicit deferral; prompt-text extraction is the cheapest thing that fills `task_refs` from scratch state as README 10.2 describes.
- R11. Skill commands are written unquoted (`--project ${CLAUDE_PLUGIN_ROOT}`) so they match their `allowed-tools` rule textually; a plugin path with spaces is a listed Windows caveat. Reason: the skills doc shows exactly this pattern for prompt-free execution; the owner's Ubuntu path has no spaces.
- R12. `jsonpath` verify engine rejected with a dedicated `unsupported_engine` message rather than implemented. Reason: F25; no consumer needs it this run and README 10.2 lists it, so the message must say it is deferred, not unknown.
- R13. Title limit 200 characters. Reason: F4, A13's title is 163 characters and the body is immutable; 200 leaves room without inviting paragraphs.
- R14. Minimum Claude Code version cited as 2.1.228 (Edit deny rule also blocking Write), tested locally on 2.1.265; `astral-sh/setup-uv@v10` (latest release v10.0.1 per `gh api`). Reason: F30.
- R15. `marketplace.json` carries the owner's email in `owner.email` because the plugins reference marks it required. Reason: validation would fail on a placeholder; it is attribution in the owner's own manifest. Owner may change it (Q6).
- R16. Task count stays 16; gates (T10) moved before lint (T13), a bootstrap commit added to T1, and every task lists exact dependency edges so the orchestrator can run up to three independent tasks in parallel. Reason: F18 and F23.
- R17. Windows shim uses `#!/usr/bin/env python` and `subprocess.call` instead of `os.execvp` when generated on Windows. Reason: F28; `python3.exe` is absent from python.org installers and `execvp` does not replace the process on Windows.
